# WEXUS — лендинг

Одностраничный лендинг портативного хранилища WEXUS. Весь код пишет ИИ, человек
проверяет результат. Поэтому главное требование к коду — **предсказуемость**:
одна задача решается одним способом, всё лежит там, где это ожидаешь найти.
Прежде чем писать новое, проверь раздел «Готовые решения» — скорее всего, оно уже есть.

## Стек

- **Vue 3** (`<script setup lang="ts">`, Composition API) + **TypeScript** (strict)
- **Tailwind CSS v4** (конфиг в CSS: `src/styles/main.css`, файла tailwind.config нет)
- **Vite** + **vite-ssg**: страница пререндерится в готовый HTML при сборке
- **VueUse** (`@vueuse/core`) — слушатели событий, наблюдатели, медиазапросы
- **Vitest** + `@vue/test-utils` — тесты; **ESLint** + **oxlint** + **Prettier**

## Команды

```bash
npm run dev      # локальный сервер с горячей перезагрузкой
npm run check    # ВСЁ: формат → линт → типы → тесты → сборка. Запускать перед сдачей задачи.
npm run test     # только тесты
npm run build    # сборка в dist/ (статические файлы, можно выкладывать на любой хостинг)
npm run preview  # посмотреть собранный dist/
```

Задача не считается выполненной, пока `npm run check` не проходит без ошибок.

## Структура

```

  App.vue                  каркас: шапка, рейка, лента экранов (SCREENS), окно заявки, JSON-LD
  config.ts                почта команды, состав команды, сервис отправки заявок
  styles/main.css          токены Tailwind, темы, каркас ленты, классы дизайн-системы
  content/                 общие данные: список экранов, FAQ, структурированные данные
  components/
    layout/                ScreenSection (обёртка экрана), TopBar, SectionRail
    ui/                    переиспользуемые элементы: BrandMark, ExpandPanel, SlidingMarker
    request/               окно заявки (RequestModal) и его части + request.data.ts
  composables/             общие useXxx: трекинг экранов, окно заявки, useInView, useRevealOnce …
  services/                работа с внешним миром (отправка заявки) — чистый TS + тесты
  sections/<экран>/        всё, что относится к одному экрану:
    XxxSection.vue           корневой компонент экрана
    *.vue                    его части
    <экран>.data.ts          данные экрана (тексты списков, строки таблиц, константы)
    *.ts                     чистая логика без Vue и DOM (расчёты, геометрия)
    useXxx.ts                composable только этого экрана (с Vue); общие — в src/composables/
    __tests__/               тесты логики и компонентов; *.ssr.spec.ts — рендер без браузера
  __tests__/               тесты всей страницы (порядок экранов в пререндере, надписи SVG)
```

## Экраны

Порядок экранов, их id, подписи в рейке и фон — только в `src/content/sections.ts` (`SECTIONS`).
`App.vue` рисует их циклом по `SECTIONS` через `SCREENS: Record<SectionId, Component>`.
Добавить экран: запись в `SECTIONS` → компонент в `SCREENS` (иначе не пройдёт проверку типов) →
корень компонента `<ScreenSection id="…">`. `src/__tests__/app.ssr.spec.ts` сверяет порядок в пререндере.
Первый и последний экран особые: на них прячется мини-шапка (`isEdgeSection`).

## Готовые решения (не писать свои копии)

| Задача | Решение |
|---|---|
| Кнопка «Оставить заявку» | `@click="openRequestModal($event)"` из `useRequestModal()` |
| Экран ленты с фоном и темой | `<ScreenSection id="…">`; его `<section>` — через `ref` и `.root` (не `$el`) |
| Класс темы по тону | `themeClassOf(tone)` из `src/content/sections.ts` |
| Тёмная карточка поверх любого экрана (окно, подсказка) | класс `.theme-raised` + свой фон (`bg-graphite/96`) |
| Раскрывающаяся панель (FAQ, условия согласия) | `<ExpandPanel id="…" :open="isOpen">`; кнопка рядом ставит `aria-expanded`/`aria-controls` |
| Бегунок сегментированного переключателя | `<SlidingMarker :target="activeButton" />`; родитель `relative`, кнопки `relative z-1` |
| Элемент в зоне видимости | `useInView(target, { threshold, once })` |
| Анимация при первом появлении | `useRevealOnce(targetRef, { threshold })` → `:class="revealClass"`; анимируемое прятать под `.is-pending`, запускать под `.is-in`. Уже учитывает пререндер, reduced motion и «элемент виден сразу при загрузке» |
| Знак WEXUS | `<BrandMark class="…" label="…">` (без label — декоративный) |
| Почта и состав команды | `TEAM_EMAIL`, `TEAM_MEMBERS` из `src/config.ts` (подставляются в согласие и подвал) |

## Правила кода

1. **Компоненты.** Только `<script setup lang="ts">`. Порядок блоков: script → template → style
   (проверяет ESLint). Пропсы — `defineProps<{…}>()`, события — `defineEmits<{…}>()` (тоже ESLint).
   Файл длиннее ~300 строк — повод вынести часть в соседний компонент той же папки
   (исключение — статичная SVG-графика).
2. **Где что лежит.**
   - Повторяющиеся данные (списки, строки таблиц, варианты выбора) — массивом в `<экран>.data.ts`
     или в `src/content/`, если нужны нескольким местам. Одиночные заголовки и абзацы — прямо в шаблоне.
   - Расчёты, форматирование, сборка запросов — чистые функции в `.ts` без Vue и DOM,
     с тестами в `__tests__/`. Компонент только вызывает их. Одно правило — одна функция
     (пример: окупаемость считается только в `breakEvenMonth`/`paybackMonth` в `economics.ts`).
   - Общее для нескольких секций — в `src/composables/` или `src/components/ui/`.
3. **Пререндер (важно).** Код в `setup` выполняется и в Node при сборке. Там нет `window`,
   `document`, `matchMedia`, `IntersectionObserver`, `requestAnimationFrame`.
   Трогать их можно только внутри `onMounted` (и в обработчиках событий) или через VueUse
   (`useEventListener('resize', …)` — без явного `window`, `useResizeObserver`, `useMediaQuery`,
   `usePreferredReducedMotion`, `useIntersectionObserver`). Нарушение ломает `npm run build`.
   Первый рендер не должен зависеть от времени, размеров окна или настроек пользователя —
   иначе HTML после гидрации не совпадёт с пререндеренным.
4. **Состояние.** Локальное — `ref`/`computed` в компоненте. Общее для страницы — модульный
   `ref` в composable (примеры: `useRequestModal`, `useSectionState`). Pinia не нужна.
   Свои элементы — только через template refs (`useTemplateRef`), без `document.querySelector`.
   Единственное исключение — `startSectionTracking` находит экраны по id из `SECTIONS`.
   Никаких глобальных CustomEvent — связь через пропсы, события или composable.
5. **Слушатели и таймеры** снимаются автоматически: VueUse или `onBeforeUnmount`.
   В колбэке IntersectionObserver берите последнюю запись (`entries.at(-1)`), а не первую.
6. **id** ставится, только если на него ссылаются `aria-*`, `label for`, якорь или тест.
   `data-*` — только если их читает код или тест.
7. **Связанные константы.** Если число в TS должно совпадать с CSS (длительность перехода,
   кегль для измерения текста, граница медиазапроса), комментарий «менять вместе» ставится
   с обеих сторон.
8. **Зависимости** не добавлять без явной необходимости.
9. **Комментарии** — по-русски и про «почему», а не «что». Дизайнерские решения из исходника
   (почему такой отступ, почему так ведёт себя анимация) сохраняются в комментариях.
   HTML-комментарий не ставится перед корневым элементом шаблона (компонент станет фрагментом) —
   пишите его в docblock скрипта.

## Стили

- **Tailwind-классы в шаблоне** — по умолчанию для раскладки, отступов, типографики, цвета.
- **`<style scoped>`** — только для: `@keyframes` и анимаций, внутренностей SVG-схем,
  состояний, которые задаёт родительский класс (`.is-on .x`), и сложных псевдоэлементов.
- Цвета и отступы — **только токены**:
  - цвета: `ink graphite cyan cyan-hover cyan-deep quartz paper deep danger`
    (`bg-deep`, `text-quartz`, `border-cyan` …). Полупрозрачные — модификатором: `bg-cyan/10`,
    `bg-fg/28`, `border-quartz/18`, а не `bg-[rgba(…)]`. Обводка внутрь в 1px — `inset-ring inset-ring-accent`.
    Исключения: атрибуты `fill`/`stroke` внутри SVG, градиенты, box-shadow, альфа из переменной.
  - зависящие от темы экрана: `text-fg`, `text-fg-dim`, `border-hair`, `bg-panel`,
    `text-accent`, `bg-board`, `bg-pill` (в `<style scoped>` — `var(--fg)`, `var(--hair)` …).
  - отступы: `s1`=8 `s2`=12 `s3`=20 `s4`=32 `s5`=56 `s6`=96 px → `p-s3`, `gap-s4`, `mt-s5`.
    Значения вне шкалы (из исходного дизайна) — произвольные: `gap-[6px]`, `text-[13.5px]`.
  - радиус: `rounded-ui` (12px). Шрифты: `font-sans`, `font-display`, `font-mono`.
  - поля экрана: `px-(--padX)`, `py-(--padY)`; ширина контента — класс `.wrap`.
- **CSS-переменные тем** (задают `.theme-dark` / `.theme-light` / `.theme-raised` в `main.css`):
  `--fg` `--fg-dim` `--hair` `--panel` `--accent` `--board` `--pill-bg` — цвета;
  `--fg-rgb` `--accent-rgb` — те же цвета тройкой для `rgba()` в SVG и графиках;
  `--wash-lo` `--wash-hi` `--sub-a` — прозрачности заливок графика экономики.
  Общие на всю страницу (`:root`): `--quartz-rgb` `--deep-rgb`, `--padX` `--padY` `--maxw`,
  `--sig-*` — такт анимации сигнала первого экрана.
- **Классы дизайн-системы** (определены в `main.css`, не дублировать):
  `.btn` `.btn-sm` `.link-quiet` `.title-display` `.title-screen` `.lede` `.note` `.mono` `.wrap` `.skip`.
  Любой Tailwind-класс их перекрывает (они в слое components). Имена новых классов не должны
  совпадать с утилитами Tailwind: например, `h-screen` — это утилита (height: 100vh),
  поэтому заголовок экрана называется `.title-screen`.
- **Брейкпоинты** (исходный лендинг был desktop-first, поэтому чаще нужны `max-*`):

  | вариант   | условие            | вариант | условие           |
  |-----------|--------------------|---------|-------------------|
  | `max-sm:` | ширина ≤ 560 px    | `lg:`   | ширина ≥ 901 px   |
  | `max-md:` | ширина ≤ 700 px    | `xl:`   | ширина ≥ 1181 px  |
  | `max-lg:` | ширина ≤ 900 px    | `short:`   | высота ≤ 900 и ширина ≥ 901 |
  | `max-xl:` | ширина ≤ 1180 px   | `shorter:` | высота ≤ 820 и ширина ≥ 901 |

  В `<style scoped>` те же значения: `@media (max-width: 900px)` и т. д.
- **Preflight Tailwind включён**: у заголовков нет размеров, у списков нет маркеров,
  кнопки прозрачные, `svg` — `display:block`. Всё это задаётся явно. Межстрочный интервал
  страницы — браузерный `normal` (как в исходнике), не 1.5.
- **Надписи в SVG** — одной строкой: `<text …>текст</text>`. Если атрибуты не помещаются,
  общие выносятся в `const LABEL = {…} as const` и подключаются `v-bind="LABEL"` или ставятся
  на родительский `<g>`. `<!-- prettier-ignore -->` не использовать. Пробел по краям текста
  сдвигает надпись при `text-anchor` — это ловит `src/__tests__/svgText.spec.ts`.
- **Анимации** обязаны уважать `prefers-reduced-motion`: вариант `motion-reduce:` или
  `@media (prefers-reduced-motion: reduce)` в scoped-стилях; в JS — `usePreferredReducedMotion()`.

## Тесты

Тесты проверяют поведение и отношения, а не Tailwind-классы и не буквальные значения констант.
Чтобы найти в тесте элемент в особом состоянии, добавьте смысловой атрибут (пример: `data-own`
у ячеек таблицы сравнения), а не проверяйте классы. Тесты не читают `legacy/`.

## Доступность

Сохранять роли и aria-атрибуты (`role="tablist"`, `aria-selected`, `aria-expanded`,
`aria-controls`, `aria-live` …), клавиатурную навигацию и видимый фокус. Декоративные SVG —
`aria-hidden="true"`, смысловые — `role="img"` + `aria-label`.

## Окно заявки

Отправка — `src/services/requestForm.ts` через сервис FormSubmit (у сайта нет своего сервера),
настройки — `src/config.ts`. При ошибке посетитель получает готовое письмо и ссылку mailto.
Гонки открытия/закрытия, итог при закрытом окне, повтор и закрытие по затемнению покрыты
`src/components/request/__tests__/requestModal.spec.ts`.
Тексты согласия на обработку данных (152-ФЗ) меняются только по просьбе владельца
(замена почты или состава команды в `config.ts` — не правка текста).

## Проверка изменений

1. `npm run check` — обязательно.
2. Визуальные изменения — открыть `npm run dev` и посмотреть в браузере на ширине
   1440, 1024, 768 и 375 px и на тёмных/светлых экранах. При сомнениях сверяться с
   `legacy/wexus_landing-7.html` (dev-сервер отдаёт его по адресу `/legacy/wexus_landing-7.html`).
