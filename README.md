# WEXUS — лендинг

Лендинг портативного хранилища WEXUS на Vue 3, TypeScript и Tailwind CSS.

## Запуск

Нужен Node.js 24 (установлен в `~/.local/node`, путь прописан в `~/.zshrc`).

```bash
npm install      # один раз, после скачивания проекта
npm run dev      # сайт на http://localhost:5173 с автообновлением
npm run build    # готовый сайт в папке dist/ — её содержимое выкладывается на хостинг
npm run check    # полная проверка: формат, линтер, типы, тесты, сборка
```

## Где что менять

- Тексты секций — `src/sections/<экран>/`
- Вопросы и ответы — `src/content/faq.ts`
- Почта для заявок и номер счётчика Метрики — `src/config.ts`
- Цвета, отступы, шрифты — `src/styles/main.css`

Правила для ИИ-разработки — в `CLAUDE.md`. Исходная версия лендинга одним файлом
лежит в `legacy/` для сверки.

## Яндекс Метрика

Счётчик 113012674 работает только на собранном сайте (не на `npm run dev`).
В интерфейсе Метрики заведены цели типа «JavaScript-событие», условие «совпадает»:

| Цель | Идентификатор | Параметры |
|---|---|---|
| Открыл окно заявки | `request_open` | `source`: topbar / hero / final / footer — какая кнопка |
| Заявка отправлена | `request_sent` | `segment` — выбранный сценарий |
| Заявка не ушла через сайт | `request_failed` | — |

Без настройки, в отчёте «Параметры визитов»: `screen` — до каких экранов дошёл посетитель
(экран засчитывается, если на нём задержались 2 секунды), `action` — переключал режимы,
выбирал объём, менял калькулятор, `faq` — какие вопросы открывали, `request_fallback` —
пользовались ли запасным письмом. Проверка на живом сайте: добавить к адресу `?_ym_debug=1`
и открыть консоль браузера.

На широком экране прокручивается лента, а не окно, поэтому карта скроллинга Метрики там
почти пустая — глубину просмотра показывает параметр `screen`.
